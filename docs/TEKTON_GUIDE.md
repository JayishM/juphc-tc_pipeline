# Tekton CI/CD Pipeline Guide: Tax Calculator

This guide provides instructions for configuring, deploying, executing, and troubleshooting the automated Tekton CI/CD pipeline for the Tax Calculator application on Kubernetes or Red Hat OpenShift.

---

## 1. Architecture & Pipeline Workflow

The Tekton Pipeline orchestrates continuous integration and continuous deployment:

```text
[ Git Clone ]
      │
      ▼
[ npm install ]
      │
      ▼
[ npm test (Jasmine) ] ── (Fails? ──> Pipeline Aborted)
      │
      ▼
[ Buildah Build & Push to ICR ]
      │
      ▼
[ Deploy to IBM Cloud Code Engine / Cluster ]
```

### Safety Gate
If any Jasmine unit test fails during `run-unit-tests`, Tekton immediately halts pipeline execution, preventing corrupt or regression-laden images from being built or pushed.

## 2. Prerequisites

1. **Kubernetes Cluster** (v1.24+) or **Red Hat OpenShift** (v4.10+) with administrative privileges.
2. **Tekton Pipelines Installed**:
   ```bash
   kubectl apply --filename https://storage.googleapis.com/tekton-releases/pipeline/latest/release.yaml
   ```
3. **Tekton CLI (`tkn`)** installed:
   ```bash
   # macOS via Homebrew
   brew install tektoncd-cli

   # Verify installation
   tkn version
   ```
4. **IBM Cloud Container Registry & IAM API Key**: For pushing images and deploying to Code Engine.

---

## 3. Configuration: Workspaces, Service Accounts & Secrets

Tekton requires a shared storage workspace (`PersistentVolumeClaim`) and authentication credentials to communicate with IBM Cloud Container Registry.

### Step 1: Create the Workspace PVC

Apply `tekton/pvc.yaml`:

```bash
kubectl apply -f tekton/pvc.yaml
```

Verify the claim:
```bash
kubectl get pvc pipeline-pvc
```

### Step 2: Configure IBM Cloud Registry & Git Credentials

Create a Kubernetes secret containing your IBM Cloud API key:

```bash
kubectl create secret generic ibmcloud-api-key \
  --from-literal=api-key="<YOUR_IBM_CLOUD_API_KEY>"

# Configure docker-registry secret for Buildah push
kubectl create secret docker-registry icr-secret \
  --docker-server=us.icr.io \
  --docker-username=iamapikey \
  --docker-password="<YOUR_IBM_CLOUD_API_KEY>" \
  --docker-email="user@example.com"
```

### Step 3: Configure Service Account

Create `pipeline-sa.yaml`:
```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: pipeline-service-account
secrets:
  - name: icr-secret
  - name: ibmcloud-api-key
```

Apply:
```bash
kubectl apply -f pipeline-sa.yaml
```

## 4. Applying Tekton Manifests (Ordered Workflow)

Because Tekton resources have dependency relationships, apply them in this exact order:

```bash
# 1. Apply Storage Workspace PVC
kubectl apply -f tekton/pvc.yaml

# 2. Apply Custom Tasks (git-clone, npm, jasmine, buildah, deploy)
kubectl apply -f tekton/tasks.yaml

# 3. Verify Tasks are registered
tkn task list

# 4. Apply Pipeline Definition
kubectl apply -f tekton/pipeline.yaml

# 5. Verify Pipeline registration
tkn pipeline list
```

---

## 5. Running the Pipeline

### Method 1: Using the Tekton CLI (`tkn`)

Launch the pipeline interactively with real-time log streaming:

```bash
tkn pipeline start tax-calculator-pipeline \
  -w name=pipeline-shared-workspace,claimName=pipeline-pvc \
  -p git-url="https://github.com/<YOUR-GITHUB-USERNAME>/tax-calculator.git" \
  -p git-revision="main" \
  -p image-name="us.icr.io/<YOUR_ICR_NAMESPACE>/tax-calculator:latest" \
  -p app-name="tax-calculator" \
  --serviceaccount="pipeline-service-account" \
  --showlog
```

### Method 2: Applying the PipelineRun Manifest

You can also trigger runs declaratively using `tekton/pipelinerun.yaml`:

```bash
# Edit tekton/pipelinerun.yaml with your specific repository and ICR namespace, then:
kubectl create -f tekton/pipelinerun.yaml
```

Follow the logs:
```bash
tkn pipelinerun logs -f -L
```

## 6. Inspecting Status, TaskRuns, and Logs

```bash
# List recent pipeline runs
tkn pipelinerun list

# Describe a specific run
tkn pipelinerun describe <PIPELINERUN_NAME>

# List all task runs generated by the pipeline
tkn taskrun list

# View logs of the latest pipelinerun
tkn pipelinerun logs -L

# View logs of a specific task within a pipeline run
tkn pipelinerun logs <PIPELINERUN_NAME> -t run-unit-tests
```

## 7. Verifying Deployment Traceability

To verify that the cloud deployment is running the exact image produced by the pipeline:

1. **Check Pipeline Build Output**: Note the image digest from the `build-and-push-image` task logs.
2. **Check Code Engine Deployment**:
   ```bash
   ibmcloud ce application get --name tax-calculator
   ```
3. **Confirm Match**: Verify that the `Image:` field matches `us.icr.io/<NAMESPACE>/tax-calculator:latest` and the active revision points to the latest deployment generation.

## 8. Troubleshooting Tekton Failures

### Issue 1: `TaskRun` fails with `workspace not bound`
- **Cause**: Workspace name in PipelineRun does not match the workspace name declared in `pipeline.yaml`.
- **Solution**: Verify that `name=pipeline-shared-workspace` matches across `pipeline.yaml` and `pipelinerun.yaml`.

### Issue 2: `run-unit-tests` fails
- **Cause**: One or more Jasmine tests failed.
- **Solution**: Inspect test output:
  ```bash
  tkn pipelinerun logs <PIPELINERUN_NAME> -t run-unit-tests
  ```
  Fix the underlying logic in `taxCalculator.js` or `spec/taxCalculator.spec.js`, commit to git, and rerun the pipeline.

### Issue 3: `buildah` fails with `permission denied`
- **Cause**: Buildah requires rootless container capability or privileged security context.
- **Solution**: Ensure your cluster allows privileged security contexts for Tekton tasks, or run in OpenShift with `anyuid` / `privileged` SCC assigned to `pipeline-service-account`:
  ```bash
  oc adm policy add-scc-to-user privileged -z pipeline-service-account
  ```
